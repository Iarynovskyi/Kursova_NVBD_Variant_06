# SSRS_Projects — аналітичні звіти `Polyclinic_Reports`

Етап 5: звіти SQL Server Reporting Services над OLAP-кубом `Polyclinic DW`.

| Файл | Призначення |
|---|---|
| `Polyclinic_Reports/Polyclinic_Reports.slnx` | Рішення Visual Studio (Report Server Project у підпапці) |
| `Polyclinic_Reports/Polyclinic_Reports/PolyclinicOLAP.rds` | Спільне джерело даних (Shared Data Source): `OLEDB-MD`, база `Polyclinic_OLAP`, Windows-автентифікація |
| `Polyclinic_Reports/Polyclinic_Reports/DS_*.rsd` | 7 спільних наборів даних (Shared Datasets) для списків параметрів |
| `Polyclinic_Reports/Polyclinic_Reports/*.rdl` | 7 звітів (5 обов'язкових варіанту + реєстр пацієнтів + підзвіт) |

## Розгортання

1. Visual Studio → `Polyclinic_Reports.slnx` → **Build** → **Deploy** (цільовий сервер `http://<сервер>/ReportServer`, налаштований у властивостях проєкту).
2. На сервері створюються папки: `Поліклініка/Звіти`, `Поліклініка/Datasets`, `Поліклініка/Data Sources`.
3. Портал: `http://<сервер>/Reports` → `Поліклініка/Звіти`.

## Звіти

| Звіт | Тип (п. 5.2) | Зміст | Параметри |
|---|---|---|---|
| **Лікарі та їх пацієнти** (обов'язковий 1) | 5.2.1 Таблиця + 5.2.5 Drill-down | Відділення → спеціальність → лікар → пацієнти; підсумки на кожному рівні; клік на лікаря розгортає пацієнтів; клік на пацієнта — drillthrough до історії хвороби; розрив сторінки між спеціальностями; карта документа | діапазон дат; **каскад** Відділення → Спеціальності (multi) → Лікарі (multi) |
| **Історія хвороби пацієнта** (обов'язковий 2) | документ + підзвіт | картка пацієнта, історія адрес (SCD2), хронологія візитів і діагнозів, кількість рецептів; розгортання підзвіту «Рецепти діагнозу»; посилання на реєстр | пошук (можна порожнім) → **каскадний** вибір пацієнта; діапазон дат |
| **Реєстр пацієнтів** | таблиця, вхід до історії | пацієнти з візитами у період, сторінками; сортування за будь-якою колонкою; клік на ПІБ — drillthrough до історії хвороби | діапазон дат; вікові групи (multi); пошук |
| **Рецепти діагнозу** | підзвіт (5.4.4) | препарати, діюча речовина, упаковки, вартість, компенсація, доплата | приховані: пацієнт, дата візиту, хвороба |
| **Завантаженість лікарів по місяцях** (обов'язковий 3) | 5.2.2 Матриця + Column/Line | лікарі × місяці з кольоровою шкалою; діаграма візитів і частки безкоштовних НСЗУ | рік (dropdown); відділення (multi); **Boolean** «Лише працюючі лікарі» |
| **Аналіз ефективності лікування** (обов'язковий 4) | 5.2.4 Дашборд | KPI-картки, radial gauge з цільовою міткою, індикатори статусу (світлофор) і тренду (стрілки), sparkline, Line Chart (рік і попередній рік), Bar Chart за тяжкістю, KPI куба по відділеннях | рік (dropdown) |
| **Статистика захворювань** (обов'язковий 5) | 5.2.3 Діаграми | **Column** (розділи МКХ-10), **Pie** (вікові групи), **Line** (сезонність), **Bar** (Топ-10 хвороб) + таблиця Топ-10 | діапазон дат з **валідацією**; розділи МКХ-10 (multi); **Boolean** «Враховувати архів Філії №2» |

## Відповідність вимогам методички

| Вимога | Реалізація |
|---|---|
| 5.1 Report Server Project, підключення до OLAP-куба, Shared Data Source | проєкт `Polyclinic_Reports`, `PolyclinicOLAP.rds` (OLEDB-MD); 7 Shared Datasets |
| 5.2 Мін. 5 типів звітів | Table, Matrix, Chart (Column / Line / Pie / Bar), Dashboard (KPI, Gauge, Indicators, Sparklines), Drill-down + Drillthrough, Subreport |
| 5.3 Параметри (мін. 4 типи) — реалізовано **5** | **Dropdown** (рік, відділення, пацієнт — значення з Dataset); **Multi-select** з «Select All» (спеціальності, лікарі, відділення, розділи МКХ-10, вікові групи); **Date Range** з валідацією (`Code.CheckRange`: початок не пізніше кінця, межі 2016–2026); **Cascading** (відділення → спеціальності → лікарі; пошук → пацієнт); **Boolean** (працюючі лікарі, архів Філії №2) |
| 5.4.1 Conditional Formatting | лікарняний від 14 днів — червоним; результат лікування кольором; теплова шкала матриці; KPI-статуси; ≥ 3–5 візитів жирним |
| 5.4.2 Interactive: Sorting, Toggle, Document Map | сортування кліком по заголовку (Лікарі, Реєстр, Статистика, Завантаженість); розгортання / згортання (лікарі, рецепти, відділення матриці); карта документа (Лікарі, Історія, Завантаженість) |
| 5.4.3 Export PDF / Excel / Word | стандартне меню експорту Report Viewer / порталу |
| 5.4.4 Subreports | «Рецепти діагнозу» всередині «Історії хвороби пацієнта» |
| 5.4.5 Page Breaks | між спеціальностями (Лікарі), розбивка таблиць на сторінки з повтором заголовків |
| 5.5 Публікація | Deploy з Visual Studio, папки `Поліклініка/Звіти`, `/Datasets`, `/Data Sources` |

Вбудований код звітів (`Code`): `DayMember` (дата → член куба), `CheckRange` (валідація діапазону дат), `RecoveryStatus` і `StatusColor` (статус KPI «Ефективність лікування», як у кубі). Багатозначні параметри передаються в MDX через `STRTOSET(@Param, CONSTRAINED)`.

## Тестування

Смоук-тест у Preview Visual Studio (24.10.2026), усі 7 звітів:

| Що перевірено | Результат |
|---|---|
| Списки параметрів зі спільних наборів даних, значення за замовчуванням | OK |
| Каскад Відділення → Спеціальності → Лікарі; пошук → пацієнт | OK |
| Multi-select: «Select All» / окремі значення (відділення, розділи МКХ-10, вікові групи) | OK |
| Boolean-перемикачі (лише працюючі лікарі; архів Філії №2) | OK |
| Валідація дат: «Візити з» пізніше «по» → повідомлення «Дата початку періоду … пізніша за дату кінця … Виправте діапазон дат.» | OK |
| Drill-down (лікар → пацієнти), drillthrough (Лікарі → Історія, Реєстр → Історія, Історія → Реєстр) | OK |
| Підзвіт «Рецепти діагнозу» (у звіті й окремо) | OK |
| Інтерактивне сортування, розрив сторінок, навігація сторінками, карта документа | OK |
| Меню експорту (Word, Excel, PowerPoint, PDF, …) | OK |

Виправлено під час тестування: поля спільних наборів даних мапляться на імена полів `.rsd` (інакше списки параметрів порожні); порожній `<Parameters/>` у drillthrough без параметрів; повільний запит історії (`NONEMPTY` за мірою діагнозів замість `NON EMPTY` з мірою іншої групи); обрізані заголовки колонок.
